- [x] 默认 CSS 1488×917 实测面板约 352×227px，两位真实成员，无水平溢出。输入、按钮、成员和状态采用紧凑比例；窄屏 CSS 410×888 同宽面板位于 x≈8..360，未超出视口。
- [x] 子菜单打开后保留名单，Escape 关闭子菜单并回到三点；再次 Escape 关闭面板并回到成员入口。验证无效邮箱与已有成员提示，未向新邮箱生成邀请。
- [x] 日历／工作台与成员等相关 31 项测试、201 个断言通过；包含原 owner 门禁、切库清理、本机限制、邀请去重及真实结果测试，新增共享嵌套浮层关闭回焦覆盖。完整 `pnpm check` 通过，最终刷新无 error/warn 或框架遮罩。
- [x] 现有邀请、默认公开只读与私有 ACL 的后端实现未改变。Web 3001、API 8721 与业务 worker 保持运行。

## 实际界面验证

使用现有 IAB、默认 CSS 视口 1488×917 和当前验收知识库。面板显示两位已加入成员，owner 显示邀请栏；当前用户显示真实本机状态，其他成员显示实际角色。

- 无效邮箱显示校验，输入已加入成员邮箱显示重复提示，不产生邀请请求；Escape 关闭且焦点返回入口。
- 外点关闭、再次打开、成员管理入口及工作页返回正常。方向键向下与初始输入焦点使用共享浮层行为。
- 公开目录更新后实际显示四个“可查看”，私有协作文档仍“仅显式授权”；原所有者文档的可见编辑器保持 contenteditable=true。
- 深色面板已检查。窄屏 CSS 约 410×888，面板左右约 x=8..402、宽约 395px，无页面横向溢出；输入、名单、管理入口不被裁切。最后恢复默认桌面浅色。
- 独立 `/invite` 页面正确显示“加入知识库”；提交格式合法但不存在的一次性邀请，得到真实不可用／邮箱不匹配提示，没有加入操作结果。移除 kind 后原文档邀请仍显示“接受文档邀请”。测试页关闭。
- 最后刷新后的主预览无相关 error/warn 和框架错误遮罩；最终截图以本轮 `knowledge-members-*.jpg` 为准。
