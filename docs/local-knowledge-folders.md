# 本地文件夹知识库

## 存储与使用

每个本地知识库对应一个用户选择的独立文件夹。创建时通过系统选择器授权一个空文件夹；“打开本地知识库”读取已有清单。创建不覆盖已有文件或已有知识库。仍可匿名使用，登录不会自动上传。

```text
所选文件夹/
├── knowledge-base.json
├── documents/<内容 SHA-256>.json
├── templates/<内容 SHA-256>.json
└── assets/<原文件 SHA-256>[.json]
```

清单包含格式标识 `fob-local-knowledge-base`、版本 `1`、知识库身份、随机 revision、文件夹元数据与概览、标签、学习秒数，以及正文、模板文件引用。正文保留编辑器 JSON 与文档元数据；模板保留独立正文快照。附件二进制不改变，旁侧同哈希 `.json` 记录原名、MIME 和大小。子目录按需创建，原文件中的路径不作为文件系统访问路径。

浏览器的 `fob-local-folders` IndexedDB 仅记录目录句柄和库 ID，不保存正文、模板或附件。授权丢失时只呈现目录入口，用户点击“授权并打开”后读取文件。不支持目录访问 API 的浏览器明确提示使用 Chrome / Edge 和安全上下文；不降级到浏览器内容存储。浏览器数据被清除后，可重新选择文件夹打开，文件内容仍在。

## 编辑与提交

编辑器使用共享的内存目录模型，保持分屏编辑、目录操作、搜索与资源来源语义。文件夹会话串行写入并合并写入期间的新变化；正文、模板和附件统一走文件夹能力，不依赖登录主体。界面区分正在保存、已保存与未保存，并提供失败重试；存在未保存内容时提示离开风险，不在浏览器中持久化恢复正文。

正文与模板采用内容寻址：先关闭所有新增内容文件，再提交新的清单。清单未写入成功时旧清单及其正文文件保持可读；成功后可清理不再引用的正文和模板文件。导入、模板操作、文件夹概览更新、重命名及转团队提交等有成功反馈的操作会等待落盘。附件上传先落盘后产生资源引用。

同源窗口使用按知识库 ID 的 Web Lock 串行打开、提交和删除；提交前检查磁盘 revision。过期写入失败并保留内存修改，不覆盖另一窗口的数据。其他来源或外部程序并发写同一文件夹不具备跨进程事务保证，宜保持一个活动写入窗口；外部编辑不属于自动同步协议。加载校验清单格式、内容哈希、知识库归属、目录引用和循环；格式不兼容或缺少文件时不呈现为空库。

删除本地知识库前明确说明磁盘文件会被删除。删除仅处理当前授权目录内的清单及约定格式的内容、附件文件，保留用户后来加入的其他文件。永久删除文档会在成功提交新清单后清除旧正文；移到回收站的正文仍受清单引用。

## 旧数据与团队边界

按产品决定，本次没有旧浏览器知识库迁移或导出恢复路径。新版初始化直接移除 `fob.local-library`、`fob.local-templates`、旧本地学习记录、本地文件夹概览恢复草稿及 `fob-local-assets` 数据库。其他窗口阻塞清理时显示错误和重试，不把旧内容导入文件夹。

本地转团队仍是用户明确触发的现有业务功能，从所选文件夹读取附件及本地目录模型，提交前检查落盘状态和版本，成功后把单向转换标记写回文件夹。团队库的 PostgreSQL / S3、成员与 ACL、身份数据、团队离线正文和界面偏好不被旧本地库清理删除。

实现入口：`local/local-folder-storage.ts` 管理文件格式与提交，`local/local-folder-session.ts` 管理句柄、权限、写入队列与状态；`assets/local-assets.ts` 管理附件，模板复用同一目录模型。执行与验证见[改造记录](../.spec/tasks/local-knowledge-folders.md)。
