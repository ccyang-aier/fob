# 知识库设置与个人库转换

知识库切换菜单统一提供“新建知识库”“知识库设置”和所有者可见的“删除知识库”。名称编辑与图标配色收进设置模态框，配色继续使用现有六套知识库头像；名称修改仅所有者可执行，配色仍是当前账户、当前知识库的浏览器偏好。

## 个人与团队入口

- 本机个人库不显示侧栏“成员”、顶栏“知识库成员”和“通知”。模板、搜索、主题、咖啡和账户入口保持各自职责。
- 个人库的旧成员链接回落到知识视图；恢复的成员页签会被移除，同时保留已有知识页签与文档作用域。
- 服务端团队库按真实成员与权限显示上述协作入口。

## 设置与转换

设置使用现有原生模态框、输入框、按钮、头像与中性反馈。包含知识库名称、六套图标配色和“团队协作”开关。选择团队后，明确提示内容将上传到当前账户，以及转换不可回退；最后的提交按钮为“转为团队并保存”。匿名用户必须先登录，现有团队库的开关保持开启并锁定。

六套配色用单行图标选项呈现，名称只在共享 Tooltip 中显示；原生单选框保留可访问名称、方向键选择和焦点描边。选中项使用共享中性底色，取消不会保存草稿配色。团队协作区域与底部按钮之间的留白为 10px。

这里的个人库是用户选择文件夹中的本地库，团队库是服务端库。本地库文件格式、目录授权与保存机制见[本地文件夹知识库](../local-knowledge-folders.md)。转换执行显式上传，不允许把仍只留在本机的内容标记为已开启协作。

1. 在当前账户作用域内读取选定本机库的目录、正文、原始附件、标签、星标、草稿和模板；只收集这个知识库的记录。附件大小继续受原上传流程约束，正文清单最大 15 MiB。
2. 创建当前已验证用户独立拥有的服务端库。附件逐个经过既有 prepare、签名 PUT、confirm 流程，保持哈希与原始字节。
3. 调用 `POST /api/knowledge-bases/:knowledgeBaseId/import-local`，以有界 multipart 发送正文清单。请求沿用可信 Origin、已验证会话和知识库权限边界；只允许 owner 写入尚未加入其他成员、没有页面的新库。
4. 服务端校验目录无环、引用完整、正文符合共享文档 schema、附件已在目标库确认，然后在一个事务中写入目录、原 UUID 的页面、Yjs `doc_state`、权限、模板、回收状态、阅读次数和索引 outbox。嵌套文件夹保持层级；原根级文档进入默认“文档”目录。
5. 前端检查导入数量，并重验本机内容与模板在迁移期间没有变化。星标、草稿、标签按当前账户和目标库保存；正文中的同源本机链接和显式资源定位改写到目标库。
6. 全部成功后保存单向转换标记并切换到团队库。原本机记录和附件保留为不出现在目录中的恢复快照，不再作为个人库使用。旧链接只对转换账户重定向到其可访问的团队库。

失败时保留原本机库，清理本次新建的目标库；清理失败给出明确错误。跨窗口转换使用当前库锁，并在提交前检查文件夹清单版本与内存快照；账户变化会取消旧作用域的后续提交，不把内容或状态写到新账户。

不提供团队转个人的操作或服务端接口。服务端库仍由现有成员、ACL、会话与知识库边界控制，不因 UI 开关绕过授权。

验证证据见 [.spec/tasks/knowledge-settings-and-presence.md](../../.spec/tasks/knowledge-settings-and-presence.md)。
