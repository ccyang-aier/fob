# 知识库成员

当前设计更新于 2026-11-07，替代此前“成员／文件夹权限”双分区。参考仓库内 Outline 的 Settings/Users：成员目录管理工作空间身份，文件夹和文档各自管理访问权限。权限模型及逐项审计统一见 [知识权限设计](../architecture/knowledge-permissions.md)。

## 成员目录

仅当前服务端知识库所有者可见侧栏成员入口、顶栏成员面板与成员页。管理员、编辑者、查看者和访客均不挂载成员查询；直接访问成员页显示无权访问状态。服务端对目录、邀请、角色修改、成员移除及成员资源权限检查再次验证所有权；本人退出知识库仍使用自助退出规则。当前角色按知识库与登录主体隔离，前台每 30 秒及窗口重新聚焦时更新，角色失效后移除入口。

成员页不再显示顶部分区菜单。内容从成员标题开始，右侧保留邀请按钮；下一行是已加入／待接受、知识库角色筛选和姓名／邮箱搜索。读取完整游标目录，人数、筛选、排序和批量选择覆盖后续 API 页。

已加入表展示成员、邮箱、真实加入时间、知识库角色、资源权限和操作菜单。姓名及加入时间支持升降序排序；不从会话时间推造“最近活跃”，也不补造邀请人。非所有者不能读取全库成员目录。

角色筛选为 144px 宽的复选框多选菜单，勾选后保持展开；“全部角色”清空筛选，筛选多个角色取并集。选中反馈放在方框内，不额外放独立对勾。

知识库角色用只读 badge 呈现：管理员、编辑者、查看者、访客；现存所有者继续显示所有者。所有者浅琥珀色、管理员浅紫色、编辑者浅绿色、查看者浅青色、访客浅蓝色，深色模式保留对应语义色。行操作与批量角色菜单共享 128px 宽、32px 高的单行徽标选项，不显示对勾，保留 ARIA 选中语义；能力说明保留在提示中。角色列与文件夹／文档权限分开。行内不直接切换角色，三点菜单中的变更角色先选择目标角色，再确认影响范围，提交成功后同步目录。本人不参与批量管理，最后一位所有者仍受保护。

选中成员后，视口底部中央显示独立操作坞，包含人数、变更角色和取消选择，不在表格前插入一行。切换工作页、打开模态时隐藏；Escape 清除选择，已展开菜单先处理 Escape。批量操作最多 100 人，后端同一事务校验，失败整体回滚。

## 每位成员的资源权限

点击姓名或该行“资源权限”入口，打开此成员专属弹窗；入口可展示真实单独授权数量，不把它称为全部可见资源数量。仅所有者可进入此弹窗，非所有者也不能通过接口检查自己的全库权限目录；资源本身的分享入口仍由具体管理授权控制。

弹窗包含身份摘要、文件夹／文档切换、资源搜索和三个业务列：

| 列 | 含义 |
| --- | --- |
| 资源 | 当前所有者实际可见的文件夹或文档；仅分享文档时不暴露私有文件夹名称 |
| 生效权限 | 可查看、可编辑、可管理，另标明默认、单独或继承来源；无权限显示横线 |
| 单独授权 | 仅修改该成员在此资源上的直接授权；“使用继承权限”移除该条直接授权 |

所有选择使用现有 Radix 风格控件、能力说明、右侧选中对勾，保留键盘导航、Escape 和焦点恢复，不使用原生 select。修改不覆盖其他成员，不改变文件夹默认值；移除直接授权后，较高的默认或继承权限仍然生效。保存显示真实 Toast，失败不伪装为成功，版本冲突要求刷新。

文件夹权限更改先围栏、后重建，文档查询在重建期间失败关闭。弹窗在前台定期刷新，避免把重建中的短暂空结果永久显示。每次最多读取 50 个资源，可继续加载；搜索在权限过滤范围内执行。

文件夹的默认访问设置仍由文件夹自身的权限入口承载，成员弹窗不修改全体成员的默认访问。文档分享入口保留文档自身的授权及继承设置。

## 邀请与实际状态

仅所有者可生成、重新生成及撤销知识库邀请，文档邀请新增访客也采用相同所有权门禁。默认邀请编辑者；后端契约也接受管理员、查看者、访客，所有权不通过普通邀请转移。链接绑定已验证邮箱、七天有效、仅可接受一次；重新生成使旧链接失效。邀请者失去所有者身份后，未接受邀请不再有效。

完整 token 仅在创建响应和当前弹窗内存中出现，链接使用 `/invite` fragment。用户自行发送链接，产品不声称已发送邮件。待接受页区分有效与过期记录；本机知识库不展示伪造的多人目录。

## 视觉与可访问性

沿用产品中性按钮、30px 控件、22px 角色／权限 badge、56px 成员行、30px 头像。表格保留横向分隔和上下边线，不增加大卡片与双层描边。窄屏成员目录只在表格内横滚，资源权限弹窗改为资源名在上、生效权限与单独授权并列在下；操作坞避让底部导航。弹窗受视口限制，深色主题使用产品语义令牌。系统侧栏、工作页导航和资源数据来源保持现有边界。

验证与截图记录见 [实施记录](../../.spec/tasks/knowledge-base-members.md) 和 [界面验收](../../.spec/tasks/knowledge-base-members-design-qa.md)。

## 弹窗与正文协作

“变更角色”入口使用统一成员图标，“创建邀请链接”使用链接图标，“完成”使用勾选图标。邀请创建底栏下留白 20px；创建成功与资源权限弹窗的完成按钮上留白 12px。新建文件夹去除默认权限字段额外的 16px 外边距，底栏上／下留白 8px／20px；默认权限菜单四项均显示语义徽标，说明保留。

评论提及与数据库人员字段通过 `page.people` 读取当前文档协作者，仅返回 userId、姓名和头像，不暴露邮箱、角色、全库成员或其余资源权限。查询先验证当前文档的实时授权和权限代次，再依据文档的知识库、个人及历史分组主体过滤，最后分页；缓存归入文档权限的失效范围。它不开放成员管理目录。
