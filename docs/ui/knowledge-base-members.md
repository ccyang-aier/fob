# 知识库成员面板

## 入口与界面

工作台右上角在搜索与主题按钮之间提供统一“知识库成员”入口，使用集中图标目录中的 FA7 user-group。入口属于当前知识库，知识库范围尚未就绪时暂不可点；切库或切号关闭旧面板，清理对应请求和临时邀请链接。

点击或方向键向下打开锚定面板，外点或 Escape 关闭并按共享规则返回焦点。桌面宽 352px、圆角 12px、内边距 14px，邀请栏与按钮高 32px，成员头像 28px、行高 52px；窄屏限制在视口内，高度不足时整体滚动，沿用共享浮层材质和深浅主题。参考原图的圆角邮箱栏、邀请按钮、邀请链接卡和头像列表，不增加重复大标题或底部管理条。

按最新批注删除“公开文档，默认只读”小字，常驻展示独立的邀请链接卡：圆形链接图标、标题与说明、胶囊“获取链接”按钮。填写邮箱后可从此处生成专属邀请；未填邮箱时聚焦邀请栏并校验，不虚构有效链接。成功后切换为真实有效期和复制链接；已有待接受邀请时显示重新生成及旧链接失效提示，仍可在待接受区域撤销。非 owner 可查看卡片，但不能生成。这里展示绑定邮箱、一次性、七天有效的知识库邀请，不把参考图的匿名文件分享条转换成匿名整库授权。

已加入成员使用真实目录、真实头像和实际角色，按所有者优先、姓名排序。API 每批最多 100 条，目录持续读取游标直到完整列出，不只展示第一页。当前用户可显示本机真实在线状态，其他成员没有远端状态数据时显示角色，不虚构在线时长。每行右侧使用参考图的圆形三点入口，提供复制邮箱；owner/admin 可进入当前知识库的成员与权限工作页面。子菜单挂在成员面板内，Escape 先关闭子菜单并回到三点，再次 Escape 关闭名单。待接受邀请单独列出，不计入已加入人数。

本机知识库说明其浏览器个人范围，不请求服务端名单或提供团队邀请；未选择知识库和未登录使用真实恢复入口。加载、失败与重试分别呈现，不用示例成员占位。

## 邀请与加入

知识库所有者（创建时获得 owner 身份）可以输入邮箱邀请普通成员，普通成员和 admin 均不显示该创建入口，服务端也拒绝其创建请求。邀请角色缺省为 member。邮箱字段校验、已加入成员检查、忙碌状态与同步重复提交防护完整；接口仍重验实际成员资格和当前权限。

现有服务生成绑定邮箱、7 天有效的一次性邀请，创建后展示真实结果与“复制链接”。不声称已发送邮件，也不生成匿名加入知识库的链接。邀请只保存 token 摘要，完整 token 仅在生成时返回；浏览器将其保留在当前面板内存，放入 `/invite` 链接的 fragment，不写入查询参数、持久化存储或成员目录。

所有者可撤销待接受邀请，或选择“重新邀请”预填原邮箱；确认重新生成前明确提示旧链接将失效。面板关闭后不从摘要恢复秘密链接，需要重新生成才能再次复制。链接卡不会因为附属名单刷新失败而丢失本次成功返回的结果；创建、撤销期间禁止复制可能即将失效的旧链接。

`/invite#kind=knowledge-base&...` 复用现有静态邀请页面，使用受邀邮箱登录后显式接受，再跳转当前知识库。邮箱不符、过期、撤销、重复使用或邀请者不再是 owner 均拒绝加入；并发接受只能成功一次，失败不留下部分成员记录。原有文档邀请 fragment 继续进入原场景，与知识库邀请分开解析。

## 默认访问

此处“公开文档”指知识库内对全体普通成员开放的页面，与匿名对外分享链接分别授权。新建知识库的默认“文档”目录为 view，正常加入的 member 继承公开页面的只读访问；未来公开页面同样适用。默认权限不包含评论、编辑或完全控制。私有目录或断开继承的页面仍需单独授权，文档／成员／分组的显式高权限继续有效，文档创建者的 full 权限不受默认访问下降影响。文档邀请的 guest 继续采用单独页面授权，不继承整库默认权限。

本次按用户最新要求，当前验收知识库已有四个公开目录的默认权限通过现有受权接口由 edit 改为 view：产品研究、概览编辑器验收、导入与嵌套验证、第三级文件夹。“协作文档”保持仅显式授权。该操作只变更目录默认值，保留显式 ACL，并通过现有权限围栏和重建流程生效；不对其他已有知识库执行无差别权限重写。所有者后续明确配置的更高目录权限属于显式策略选择。

## 组件与数据边界

`shell/system-bar` 只组合入口；`knowledge/organization` 管理成员面板、完整游标目录、邀请传输与接受场景。`KnowledgeQueryProvider` 在当前面板生命周期内隔离查询，键包含知识库和主体，隐藏面板不持续查询。成员和待接受邀请分别读取，列表错误有独立恢复入口；名单在打开期间定期刷新。

复用 `/api/knowledge-bases/:knowledgeBaseId/members`、`invitations` 及 `accept`，不创建新的账户目录或跨库发现接口。返回成员摘要时补充已有账户头像；guest 不获得目录枚举权限。业务服务从验证会话取得主体并在知识库锁后重读权限。无新表或数据库迁移。

执行与证据见 [知识库成员实施记录](../../.spec/tasks/knowledge-base-members.md)。
