# 知识库成员与文件夹权限

当前设计对应用户选定的两张 UX（2026-11-04）。知识库仍是唯一工作空间和权限边界；系统侧栏由 shell 提供。管理页只保留“成员”和“文件夹权限”两个分区，不新增侧栏、介绍卡片或统计面板。

2026-11-05 细化：顶部使用两个 30px 切换按钮，选中时采用共享中性背景、保留 `aria-pressed`，移除下划线和通栏分隔线；桌面内容上留白 24px，窄屏 20px。成员、待接受邀请与文件夹权限表仅保留上下外框及横向行分隔线，移除左右外框和外框圆角；窄屏仍在表格内部横滚。邀请、有效权限查询和添加授权分别使用统一目录的 FA7 `user-plus`、`eye`、`shield-halved`，按钮内容、权限门禁与操作保持原有语义。

## 成员

内容区采用紧凑标题、右侧黑色邀请按钮、已加入／待接受切换与姓名／邮箱搜索。表头约 34px，成员行约 56px，头像 30px；姓名与邮箱合并一列，第三个业务列使用数据库中的真实加入日期。四种角色统一使用 22px 高的徽标：所有者淡杏、管理员淡紫、成员中性灰、访客淡蓝。角色触发器与徽标分开承担交互反馈，菜单中的角色徽标配简短权限说明，选中标记统一靠右。字号、边框、圆角及操作反馈沿用产品令牌。

目录读取全部游标页，人数及搜索覆盖完整目录。所有者和管理员只可选择其有权管理的成员，最后一位所有者不可选。选择后在视口底部中央显示独立操作坞，包含选中人数、批量变更角色和取消选择；不插入表格上方、不改变表头位置。操作坞仅在成员页可见时显示，切换工作页隐藏，返回后保留选择；Escape 或取消按钮清除选择，已打开的菜单优先响应 Escape。窄屏为底部导航预留空间。单次最多 100 人；服务端在同一知识库事务中校验全部成员、角色上限及剩余所有者，任何一项失败全部回滚。每行保留角色菜单与移除确认，真实结果通过共享 Toast 反馈。

owner 可创建绑定邮箱、7 天有效的一次性邀请；admin 可按既有角色上限查看和撤销邀请，不能创建。待接受页区分有效及过期记录，支持撤销与重新生成。重新生成前提示旧链接失效；不声称已发送邮件。完整 token 仅在创建时返回并保留在当前弹窗内存，复制链接使用 `/invite` fragment，不持久化秘密。受邀人以相同的已验证邮箱登录后主动接受；过期、撤销、重复、邮箱不符或邀请者失权均拒绝加入。

## 文件夹权限矩阵

表格展示真实文件夹树、库内普通成员默认权限、最多三位成员的单独授权，以及完整的显式授权条数。成员较多时，例外明细和有效权限查询仍可访问全部成员。搜索保留命中文件夹的祖先，折叠不改变存储。没有权限或没有数据时不生成示例成员、文件夹或徽标。

- 普通成员默认值与个人授权分开显示；蓝色为查看、淡杏为评论、绿色为编辑、紫色为管理，横线表示该列没有授权。
- “添加授权”选择当前库的文件夹、成员和权限；单元格及例外入口打开同一权限编辑弹窗，可修改默认值、增加／修改／移除个人授权。
- 所有权限、成员和文件夹选择均复用共享 Radix 菜单，不使用系统原生下拉框。权限项显示能力说明和右侧选中标记；可增长的成员／文件夹选项支持搜索，成员选项同时显示头像、姓名与邮箱。权限弹窗中的授权名单包含真实头像、授权数量与权限徽标，移除入口在悬停或键盘定位时出现，触屏始终显示；取消不提交草稿。
- 子文件夹可显式启用继承；根文件夹不能继承。继承父级默认值和个人授权，默认值来自最近的独立文件夹。个人正向授权按较高级别合并；降低继承权限须先取消继承，界面明确说明。
- 有效权限查询将已解析的默认值与个人授权取较高级别，guest 不获得库内普通成员默认值。它展示文件夹基准权限；页面断开继承或单独 ACL 仍以页面授权为准。
- 仅 owner/admin 可写文件夹策略；普通成员只读，guest 不可枚举目录。所有请求以 `knowledgeBaseId` 为作用域，个人授权必须引用同库的真实成员。

## 权限一致性与存储

`resources.teamspace.inherits_access` 默认为 false，保持已有文件夹的独立默认值。`resources.teamspace_member_access` 保存复合知识库／文件夹／成员授权，复合外键随文件夹或成员删除而清理，强制 RLS 隔离知识库。文件夹策略使用现有 metadata revision 做乐观并发控制，旧弹窗不能覆盖已更新的策略。

授权修改与权限围栏在同一事务提交：目标文件夹和所有沿途启用继承的子文件夹立即使文档／索引 ACL 失效，再经现有 outbox 与 Worker 重建。重建前失败关闭，不保留已撤销的访问。移动继承文件夹同样围栏并重新计算；页面的独立继承边界仍生效。文档分享的有效成员与订阅创建路径使用相同文件夹权限根。

已有数据库执行一次加法升级：

```powershell
bun --env-file=.env.fob.local backend/server/scripts/upgrade-folder-access.ts
pnpm database:status
```

新库由 Drizzle 和 `current.sql` 直接初始化。升级不改写现有默认值、文档或成员，不删除原数据。

## 群组退役

删除群组页面、导航、前端 client/hooks、业务管理模块及全部群组 CRUD／成员路由；文档分享目录不再返回群组，公开授权输入拒绝群组主体。新产品流程只管理成员与个人授权。

旧 group/group_member 表和权限引擎中的既有主体解析仅保留读取兼容，避免历史授权突然扩大或丢失；不提供管理 API。文档分享中的旧策略标为“历史授权”，只读呈现，不提供创建或修改入口。当前开发库退役前核查为两个空旧记录、零成员关系、零群组 ACL；没有为改界面删除用户数据。
