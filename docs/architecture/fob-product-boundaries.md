# Fob 独立产品与完整复制方案

## 1. 决策与验收目标

Fob（Fusion One Book）在 `C:\AIWorks\26Coding\fob` 独立开发和部署。此次采用**复制实现、独立演进**：Fouc 原有知识库及其他功能保留，Fob 获得现有知识库的完整实现。此次不在 Fouc 内删除模块、修改入口、接入连接器或调整数据。

必须同时满足：

1. Fouc 工作树、运行服务和数据不因本次工作变化。
2. Fob 不借助 Fouc 源码目录、node_modules、数据库、账号会话、设备服务或 Tauri 即可安装、构建和运行。
3. 复制知识库前端、共享文档协议、业务服务及媒体处理依赖；迁移完整性以源码基线、必要测试和真实操作共同证明。
4. 布局、桌宠、账号、主题、设置、项目切换和项目成员管理复用 Fouc 实现，仅做品牌、宿主和部署隔离适配。
5. Web 浏览器的本机知识库继续属于浏览器，不因登录自动上传或替换；服务端知识库保持其资源授权。

项目成员 API 和当前成员页面分别复制。当前页面含本机参考目录与界面状态，尚不是服务端成员管理的完整接线；不得用该页面的演示操作证明服务端成员变更已验收。

包名、用户可见品牌、环境变量和浏览器持久化前缀统一为 Fob。保留部分源文件名或 CSS 结构以降低无收益改动；名称本身不构成对 Fouc 的运行依赖。

## 4. 数据与项目范围

### 4.1 独立权威来源

- Fob 使用独立 PostgreSQL 数据库与角色、独立对象存储 bucket/前缀、独立 Redis/作业命名空间。开发端口与 Compose 项目名也独立。
- `auth` 及账户相关表仅属于 Fob；`resources` 中的项目、知识库、文档、ACL、评论、索引、模型与资产等保持原实现的归属外键及 RLS。
- 正文继续以 Yjs/`doc_state` 为持久权威；关系元数据在 PostgreSQL；原文件在对象存储；派生索引可重建。不得只复制页面标题而遗漏正文、协作更新、历史或原文件。
- 浏览器项目、知识库、原文件、Yjs 状态和页面 UI 恢复记录按 Fob 命名空间与浏览器 origin 隔离。换端口/域名不会自动获得 Fouc 的 IndexedDB。
- 开发示例必须在 Fob 数据库独立生成，不把示例当作已迁移的用户文件。

### 4.2 项目与知识库的保留关系

用户所说的“工作空间”沿用现有项目管理设计：项目是工作台业务范围，知识库为独立、多实例资源，通过 `knowledge_base_project` 配置开放项目。顶部切换 Fob 的真实 `projectId`；只有项目成员、知识库开放范围与库成员同时满足时才可发现，再逐项校验页面 ACL。

Fob 不创建 `workspace` 表，不把所有知识库塞进虚构默认项目，不把 Fouc 项目 ID 当成自动可访问 Fob 的授权证明。两个产品即使数据复制后某些 UUID 相同，其身份和授权仍相互独立。

### 4.3 现有数据的独立复制

代码复制与数据复制分开执行。默认新建空 Fob 数据库，不自动读取 `.env.fouc.local` 或复制用户密钥。

若需要带入 Fouc 现有数据，按以下单次、可核对的交接完成，源端全程只读：

1. 明确源/目标 URL、数据库名、对象存储目录和要迁移的主体；验证目标为 Fob 专属空库，拒绝源目标相同。
2. 在一致性快照中导出账户所需数据、项目/成员、知识库/开放关系、文件夹/页面、Yjs 正文与历史、权限/组/邀请、评论、通知、资产元数据及相关知识作业。共享源 schema 时只选知识与项目所需表，不带频道/任务业务。
3. 在目标库恢复相同 ID，保留父子与组合外键；建立独立登录会话与密钥。现有密码散列可随账户显式复制，活动 session、验证码、PAT/OAuth access/refresh token 不复制；要求重新登录、重新授权。待接受邀请和分享 token 须按交接目标决定重新签发，不能默认对外继续有效。
4. 复制每个实际原文件与其元数据，核对大小/哈希；复制历史/协作正文。只迁移派生状态时必须能重建索引，不能用空索引掩盖丢失正文。
5. 对浏览器本机数据，从 Fouc 所在 origin 显式导出包含元数据、页面正文与原文件的资源包，在 Fob origin 导入。不得尝试从新 origin 直接读取旧 IndexedDB，也不得因登录上传本机内容。
6. 核对资源数量、关系外键、正文哈希、附件哈希、权限交集、非成员拒绝、协作与搜索；完成前源内容继续由 Fouc 正常使用。

此次不实施有损的原库改名、表移动、源库删除或双向同步。若没有显式数据复制输入，应交付空库部署和独立开发示例，并如实记录尚未复制实际数据。

## 5. 账号、权限与浏览器安全边界

- 复制 Better Auth 实现，包括注册/登录、邮箱验证、找回、用户资料、OAuth 支持与节流；各产品有不同数据库、认证 secret、cookie prefix、回调 URL、trusted origins、邮件链接和 OAuth 应用配置。
- 同一个人可以在两个产品注册同邮箱，不意味着两个账户自动相同、成员权限共享或会话互通。
- localhost 不同端口仍可能共享 cookie 域；必须使用产品独立 cookie 名。各自的 localStorage、IndexedDB、广播频道和缓存前缀也独立。
- 项目角色由项目模块管理，知识库角色与页面 ACL 由知识库管理。两层权限都不因为 UI 可见、项目关联、搜索命中或连接器存在而放宽。
- 服务端沿用事务范围、RLS、组合外键、令牌范围、WebSocket/协作操作重验和失效订阅关闭。
- 分享/邀请、签名下载、MCP 令牌只能由 Fob 服务校验；密钥和存储配置不从 Fouc 隐式读取。
- 将来需要统一登录时，可分别接入同一个外部 IdP；不共享数据库、不依赖 Fouc 启动，也不将 SSO 变成资源授权。

## 6. Web 宿主与部署

前端保留 Next.js App Router 与原有静态导出模式，业务 API、实时协作、MCP 和作业继续由 Bun 服务承担。生产入口由反向代理分别转发 Web 静态文件及 API/WebSocket；前端编译时配置自身 API origin。Fob 不强制引入 Next.js API 层或新的远程执行平台。

部署组件：Web、业务服务（可按角色拆分 API/协作/MCP）、知识后台 worker、PostgreSQL/搜索扩展、对象存储、按需 Redis、媒体 worker。所有运行与部署文件在 Fob 仓库内，不挂载 `../fouc`。

不要求桌面进程、原生窗口按钮、自动更新、原生文件对话框或设备 Agent。浏览器能够支持的文件选择、下载、剪贴板、IndexedDB 和 WebSocket 继续复用；原本只属于桌面宿主的系统功能从 Web 导航移除。

## 7. Fouc 与 Fob 的未来连接

本次不改 Fouc。后续可在 Fouc 独立实施 Fob Provider：显式配置实例 URL 与授权身份，经现有 Connector Policy 调用 Fob HTTP API/MCP。先提供搜索、读取、引用、原文跳转，再扩展受授权写入。

Fob 是其知识的唯一权威。Fouc 保存外部引用与必要证据，不能直接连接 Fob 数据库，也不凭 Fouc 项目成员资格跳过 Fob ACL。对外文档引用包含实例、知识库和页面身份；写入由 Fob 记录来源并继续接受权限校验。

## 8. 实施顺序与完成门槛

1. **冻结对照**：记录源提交、脏文件状态、知识/桌宠源码基线，建立 Fob 仓库；全程检查源未变。
2. **复制基础**：完整复制知识、公共控件、身份、项目、设置、主题、布局、桌宠、后端与媒体处理；改包名/产品命名空间，独立安装依赖。
3. **解除宿主牵连**：前端组合仅保留 Fob 工作对象；后端移除非知识产品的组合入口；去掉 Tauri 与设备启动要求，保留浏览器本机资源。
4. **隔离部署与身份**：独立环境变量、端口、数据库、cookie/secret、bucket/队列和邮件链接；落地开发启动与生产部署文件。
5. **完整性与权限验收**：源码基线无遗漏；前后端/共享包检查；知识必要测试；真实 Web 创建项目→创建库→编辑/刷新→文件与设置/桌宠流程；可用服务下执行协作和权限验证。
6. **独立数据交接**：有明确输入时按 §4.3 只读复制；没有输入时明确交付新库与种子数据，不能声称现有用户数据已迁移。
7. **交付**：复核前端规则、清理临时材料、保留运行服务、记录真实通过和阻塞项、提交 Fob；Fouc 不产生本次提交。

配置模型、SMTP、对象存储、媒体计算、真实 OAuth 身份和多用户协作的完整验收必须使用真实服务。源码/单测通过不得替代真实集成结论。
