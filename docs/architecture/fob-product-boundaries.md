# Fob 产品定位与架构

## 产品定位

Fob（Fusion One Book）是面向个人与团队的 Web 知识工作空间，集文档编辑、文件管理、检索、协作与 AI 于一体。愿景是让知识易于记录、组织、发现和复用，成为持续积累的共同资产。

一个知识库就是一个工作空间，也是内容组织与资源授权的基本边界。个人可在浏览器本地管理知识，团队通过服务端知识库共享内容、协同编辑并管理权限。

本文维护当前产品与架构决策，实施进度和验证证据统一记录于 `.spec/tasks/`。

## 核心能力

| 能力 | 范围 |
| --- | --- |
| 知识组织 | 多知识库、文件夹、页面树、标签、星标、最近记录、草稿、回收站 |
| 内容编辑 | 富文本与 Markdown、稳定块 ID、表格与合并、分栏、代码、文件与图片、引用、数据库块、AI 块、撤销重做 |
| 文档与文件 | 阅读编辑、目录、分屏、PDF、DOC/DOCX、PPTX、表格、JSON、文本、原文件重新关联、导入导出 |
| 协作 | Yjs/Hocuspocus、在线成员、评论与回复、问题、建议、版本与检查点、断线恢复 |
| 模板与订阅 | 本机及团队模板、正文快照与应用、文章和文件夹订阅、事件与通知收件箱 |
| 权限与分享 | 库成员、分组、邀请、文件夹可见性、页面 ACL 与继承、分享、PAT/OAuth、撤权 |
| 检索 | 全文、向量与混合检索、索引作业、块定位、反向链接、授权过滤 |
| AI 与 MCP | 模型配置、任务、流式结果、建议写回与审阅、用量、工具注册、HTTP MCP 与令牌 |
| 资产处理 | 库内哈希、S3 直传与校验、签名下载、IndexedDB、媒体处理、重试与失败反馈 |
| 账户体验 | 身份认证、个人资料、界面偏好、每日签到、咖啡余额与全局精灵 |

各能力如实呈现配置要求、可用状态和错误；具体可用性以真实环境验证为准。

## 系统架构

前端使用 Next.js App Router、React、TypeScript、Tailwind CSS v4 和现有 Radix 风格组件，通过 HTTP/WebSocket 访问业务服务。TypeScript 业务服务由 Bun 运行，API 保持 Node 兼容；Python 媒体 worker 独立处理文档与多模态作业。

| 路径 | 职责 |
| --- | --- |
| `src/app` | Web 入口、全局材质与字体、根 Provider、全局精灵宿主 |
| `src/shell` | 系统侧栏、顶栏、页签与分屏、主容器、系统搜索及全局偏好入口 |
| `src/features/knowledge` | 知识库管理、资源目录、成员与权限、编辑器、预览、本地及服务端资源适配 |
| `src/features/identity` | 注册、登录、验证、找回、个人资料、OAuth 与会话交互 |
| `src/features/settings` | 通用、外观、字体、语言和关于 |
| `src/features/companion` | 精灵动作、拖动、菜单、气泡及状态 |
| `src/features/rewards` | 每日签到、日历、咖啡余额与账户账本交互 |
| `src/components`、`src/lib` | 共享控件、主题、偏好及浏览器视图恢复 |
| `backend/server` | 身份、知识库、权限、模型、协作、检索、作业、账户权益及 MCP |
| `shared` | 跨运行时契约、知识文档语义、块与 Markdown |
| `services/media-worker` | 文档解析与多模态处理 |
| `public` | 图标、字体、品牌及文档预览资源 |

前端通过 `@fob/server/knowledge-api` 的 `import type` 引用服务端公开类型，运行时纯协议使用 `@fob/shared`。查询、授权和业务操作由对应领域服务负责。

## 知识库与客户端架构

### 工作空间与导航

- 成员、分组、页面、文件夹、标签、模板、ACL 及业务操作直接以 `knowledgeBaseId` 为作用域。服务端目录列出当前账号有成员资格的知识库，创建知识库同时建立 owner 成员关系。
- `KnowledgeBaseProvider` 管理可访问目录与当前选择，区分浏览器本地库和服务端团队库；`KnowledgeBaseSwitcher` 在侧栏顶部提供选择、新建、重命名和删除入口。创建弹窗由 Provider 统一拥有，切换器与空状态共用。
- shell 通过 `KnowledgeNavigationProvider` 提供唯一系统侧栏出口与展开/收起状态。资源适配器通过 Portal 提供目录，负责查询、ACL、创建、移动和编辑；窄屏将同一导航呈现为抽屉。
- 侧栏组织主页、星标、草稿、回收站、文件夹、标签、最近记录、成员和模板入口。展开时底部依次放置设置、帮助、分隔线与签到卡片；收起时隐藏签到入口，设置位于最底部。签到卡片复用资源卡片材质，咖啡图标不带底色容器，进度和按钮展示真实签到状态。
- 系统栏右侧依次提供搜索、主题切换、消息、咖啡和账户菜单。咖啡使用单图标与中性色数量角标，完整余额保留在可访问名称和提示中；无已确认数据时不显示虚构数量。文档工具栏只保留目录/缩略图、星标及文档操作，不重复提供所属文件夹入口。

### 页签与视图恢复

- shell 统一拥有文档页签与分屏状态。分屏由一对顶层页签组成，支持独立选择、关闭、比例调整和恢复；正文承载列表、编辑器、成员等内容，以及目录和评论等辅助面板。
- 视图恢复、页签与检索缓存按 `principal + source + knowledgeBaseId` 隔离。本地和服务端资源适配器分别创建编辑器，隐藏、重排及正文加载变化保持编辑器状态。
- 当前导航所属页签负责跨功能文档跳转和通知发布。成员页保留最近知识目录，目录操作返回所属知识页签；关闭最后一个知识页签时保留导航宿主。

### 搜索与文档链接

- 系统搜索查询当前知识库的真实标题与正文，结果受服务端 ACL 约束；切库取消旧请求，并按新作用域更新结果。
- 文档链接携带资源来源、`knowledgeBaseId` 和页面身份。进入时等待当前主体的可访问目录并选择目标库，本地校验实际归属和删除状态，服务端验证成员资格与页面 ACL。
- 不可访问的目标提供明确错误与恢复入口；通知由当前资源所有者管理。

## 数据与权限

### 数据权威与持久化

- Yjs/`doc_state` 是文档正文的持久化权威；PostgreSQL 保存关系元数据、成员、权限、订阅和账本，S3 保存原文件，派生检索索引支持重建。
- 资源直接归属知识库，通过事务作用域、组合外键和 FORCE RLS 维护隔离。附件按库内哈希校验，通过授权上传、签名下载和媒体作业处理。
- 本地知识库支持匿名使用与持久化，知识库、附件、Yjs 与界面恢复状态保存在 Fob 浏览器命名空间内，受 origin 隔离。本地与服务端按显式资源来源选择；登录、退出和切号保持本地内容归属，上传或导入由用户明确触发。
- 数据库与角色、对象存储、Redis/作业命名空间、环境变量、认证密钥、Cookie 及浏览器存储键均使用 Fob 自有配置。

### 身份与授权

- Better Auth 提供注册、登录、验证、找回、资料、OAuth 和节流。账户数据库、会话、Cookie、回调地址、trusted origins、邮件链接和 OAuth 应用配置由 Fob 管理；Cookie 使用产品前缀。
- 资源访问同时受知识库成员资格、角色、分组、文件夹权限及页面 ACL 约束。服务端执行授权，HTTP、WebSocket、搜索与 MCP 使用相同资源规则；令牌作用域、操作重验和撤权断开覆盖长连接与外部调用。
- 服务端整库重命名和删除仅 owner 可执行，UI 按真实角色呈现操作。删除需确认并说明不可撤销后果；本地删除仅清理目标库的目录、文档、标签、模板与附件。
- 知识库成员和权限在当前库管理，全局设置负责账号与界面偏好；浏览器本地库按个人资源呈现。

## 模板、订阅与账户资产

### 模板

- 模板中心归属当前知识库。团队模板保存源文档的独立正文快照，创建需源页面 edit 权限；列出、预览和应用重验源页面 view，应用还需目标文件夹 edit。创建者或库 owner/admin 可管理模板。
- 正文通过共享 schema 校验，同库附件独立授权。应用时重建块 ID，清理源评论、建议、数据库绑定和运行中 AI 任务身份。
- 修改模板信息保持正文快照独立，已创建文档的生命周期独立于模板删除。本机模板使用 Fob 浏览器存储，与登录状态独立。

### 订阅与通知

- 订阅目标为文章或文件夹，主体来自服务端会话。文件夹订阅覆盖当前归属文章，新建、改名、正文和文件变化接入通知收件箱与事件通道；跨账户订阅由服务端库提供。
- 页面与文件夹订阅重叠时按接收者去重，连续正文更新合并，作者只接收他人的变更通知。
- 投递和读取均重验成员资格与页面 ACL，失权时保护标题与内容。删除目标或成员清理相应订阅，取消订阅阻断后续通知。

### 签到与咖啡

- 咖啡是账户资产，按已验证账户及 `Asia/Shanghai` 日历日签到，每日领取 1 杯。
- `resources.coffee_ledger` 是只增账本，余额由真实记录汇总，同账户同日唯一；主体和时间由已验证会话及数据库时钟决定。
- 账户 RLS 与知识库事务作用域分别设置并清除，退出和切号隔离余额缓存。

## 全局界面组件

### 认证与资料背景

登录模态框和 `/auth` 页面共用 `GradientASCII` 背景与登录表单；`AuthBackdrop` 使用 horizon 蓝白参数、字符、鼠标扰动和点击波纹，左栏呈现品牌、简洁文案和轮播线索。`ProfileBackdrop` 提供个人资料的银色缎带封面。WebGL2 背景不可见时暂停，GPU 对象清理需兼容 StrictMode 的 context 复用。

### 全局精灵

精灵由根布局唯一挂载。`CompanionLayer` 使用覆盖视口的 manual popover 顶层宿主，逻辑上归属活动模态框，保持焦点、Escape 和表单操作；位置与拖拽独立于弹窗的 transform 和 overflow。

气泡以被动 status 展示，随拖拽移动并避让视口，Escape 由活动交互层处理。宿主空白区域不接收指针，开关模态框与全屏切换保持同一实例和状态；`OverlayRootContext` 仅承载精灵内部浮层控件。

布局、共享控件、图标及交互状态遵循 [AI 前端规则](../../AI_FRONTEND_RULES.md)。

## 开发、部署与验收

### 运行与部署

- 前端静态导出，由 Nginx 提供页面并反代 API/WebSocket；业务服务、作业 worker 和 Python 媒体服务分别运行。
- `dev:init` 初始化开发环境，`dev:all` 保持源码热更新服务常驻。默认开发端口为 Web 3001、API/协作/MCP 8721、PostgreSQL 55433、Redis 56380、S3 59010/59011、媒体 8920。
- `media:dev` 单独启动 Python 媒体服务，监听 `media_worker/` 的 Python 源码并自动重启；Windows 后台会话由 Node 监听器回收本次启动的 Python 进程树，再拉起新进程。媒体子进程只接收媒体配置与必要的系统环境，认证 token 和下载 origin 来自当前 Fob 配置。
- 生产部署使用 `Dockerfile.web`、`Dockerfile.server`、媒体镜像、`compose.production.yaml` 及数据库、队列与存储初始化工具；配置 HTTPS Web/S3 origin、非超级用户运行角色和认证与存储密钥。

### 验收要求

- 验证本地与团队知识库的创建、切换、重命名、删除，编辑后刷新恢复正文和附件，切库与切号保持数据隔离。
- 验证真实成员、分组、页面 ACL、标题正文搜索、文档链接、订阅通知与撤权行为，确保搜索和通知遵守相同授权范围。
- 验证页签、分屏、编辑状态恢复及桌面浏览器与窄屏流程，并复核共享前端规则。
- 根据修改范围执行类型、架构边界与领域检查，保留可复核的验证证据。
- 完整生产部署及依赖 SMTP/OAuth、模型、向量、视觉和媒体解析的能力仍需目标环境验证；配置检查不替代端到端验收，具体状态记录于 `.spec/tasks/`。
