# Fob 独立产品边界与拆分方案

## 1. 产品决策与验收目标

Fob（Fusion One Book）在 C:\AIWorks\26Coding\fob 独立开发和部署。采用复制实现、独立演进：Fouc 原有知识库及其他功能保留，Fob 获得已有知识能力与基础交互实现。Fob 的业务模型以本节当前决策为准。

**一个知识库就是一个独立工作空间。** Fob 只使用 knowledgeBaseId，不保留额外项目、项目成员、项目与知识库关联或 workspaceId。顶部沿用原项目切换器的样式、头像与交互设计，操作改为直接切换、新建、重命名和删除知识库。下方不再显示第二个知识库标题或选择器。

验收要求：Fouc 文件、服务和数据不因本次工作变化；Fob 无需兄弟仓库、数据库、登录态、设备服务或 Tauri 即可安装、开发和部署；现有编辑器、协作、权限、资产、搜索、AI、MCP、导入导出和浏览器本地知识能力完整承接。

Fob 不分发 Fouc 的频道聊天、项目任务、Agent 管理、设备连接器工作台、社区和桌面壳。知识库自己的 AI 作业、数据库块、文件和编辑能力保留。目录内部沿用的 teamspace、sidebar-project-tree 等文件夹实现名称不代表存在产品项目实体。

### 2.1 唯一导航与作用域

唯一系统侧栏顶部为知识库切换器，其下直接是主页、星标、草稿、回收站、文件夹、标签和最近记录；底部是当前库成员、账号、主题和全局偏好。正文只承载文档列表、编辑器、成员或其他内容。文档目录、评论和引用分屏是内容辅助面板。

KnowledgeBaseProvider 负责可访问知识库目录与选择；本地库来源于浏览器存储，团队库直接来源于当前账号的知识库成员资格。KnowledgeBaseSwitcher 复制原切换器视觉与头像实现，创建弹窗由 Provider 统一拥有，顶部和空状态共用入口。

KnowledgeNavigationProvider 由 shell 提供唯一侧栏出口。资源适配器通过 Portal 把目录放入该出口，保留原查询、ACL、创建、移动和编辑逻辑。shell 独占展开/收起状态；窄屏将同一导航呈现为抽屉，不能再次创建内层系统侧栏。

视图恢复、页签和检索缓存以 principal + source + knowledgeBaseId 隔离。多个知识页签保留各自编辑器；只有当前导航所属页签处理跨功能跳转和通知。成员页保留最近知识目录，点击目录回到所属知识页签；关闭最后知识页签仍保留一个导航宿主。

系统搜索查询当前知识库的真实标题与正文，并沿用服务端 ACL。切库取消旧请求，不能搜索别库，也不能用菜单文字匹配代替内容检索。通知跟随当前资源所有者，隐藏页签不能覆盖或清空它。

文档链接只携带来源、knowledgeBaseId 和页面身份。进入时等待当前主体的可访问目录，选择目标库；本地校验文档实际归属及删除状态，服务端继续校验库权限与页面 ACL。不可访问的链接显示明确错误与恢复入口。正文变化不通过临时加载态卸载已验证的编辑器。

### 2.2 成员与管理

成员入口管理当前知识库的真实成员、分组和文件夹权限，不再管理另一套项目成员。浏览器本地库明确为个人资源，不显示虚构团队或模拟保存成功。

服务端整库重命名和删除仅 owner 可执行，UI 依据真实角色显示，服务端独立强制校验。删除必须确认并突出不可撤销后果；本地删除只移除该库的目录、文档、标签和附件，保留其他库。全局设置只管理账号/界面偏好，不冒充知识库管理。

### 2.3 登录背景与全局精灵

登录模态框和独立 /auth 页面共用 GradientASCII 左栏及原登录表单。背景组件位于 src/components/backgrounds/gradient-ascii.tsx，直接复制用户提供的 WebGL2 实现，AuthBackdrop 配置同一组 horizon 蓝白参数、字符、鼠标扰动和点击波纹；左侧只保留品牌、简洁文案及轮播线索，移除模拟任务卡。独立 ProfileBackdrop 保留个人资料的原银色缎带封面。背景不可见时暂停，释放 GPU 对象时不主动丢失 StrictMode 会复用的 context，两产品各自拥有相同源码，不互相导入运行代码。

精灵仍由根布局唯一挂载。CompanionLayer 使用覆盖视口的 manual popover 顶层宿主，保留原生模态框的焦点、Escape 和表单操作；宿主逻辑上位于活动模态框内以保持可交互，但位置、拖拽、菜单与气泡独立于弹窗的 transform 和 overflow。气泡以被动 status 展示，不注册 Escape 关闭层，保留拖拽跟随与视口避让。空白区域不接收指针，只有精灵及其控件接收事件；开关模态框与全屏切换保持同一实例和状态。OverlayRootContext 仅让精灵内部控件跟随该浮层，其他系统菜单仍按原有规则挂载。

保留源码不等于原本尚未实现或依赖外部服务的能力已经完成验收。真实配置要求、禁用状态和错误反馈如实保留。

.spec/source-baseline.json 记录原 Fouc 提交及 886 个知识/桌宠文件。品牌规范化仅替换 FOUC/Fouc/fouc，文本按 LF、二进制按原字节计算 SHA-256。独立演进的修改必须逐路径记录原因与精确哈希；被移除的重复导航和项目耦合必须显式记录删除原因。不能用排除整个目录或移除校验掩盖能力丢失。

## 4. 数据边界与交接

### 4.1 独立权威

Fob 使用独立 PostgreSQL 数据库与角色、S3 bucket、Redis/作业命名空间、认证密钥和服务端口。当前业务 schema 为 32 张表，其中 27 张资源表启用 FORCE RLS；无 project、project_member 和 knowledge_base_project。每个知识内容资源直接归属知识库，保持组合外键和权限隔离。

Yjs/doc_state 是正文持久权威，关系元数据在 PostgreSQL，原文件在对象存储，派生检索可重建。复制标题不能代替正文、协作更新、历史和原文件交接。

浏览器知识库、附件、Yjs 与 UI 恢复状态均使用 Fob 命名空间并受 origin 隔离。登录、退出和账号切换不自动上传、替换或迁移本地内容。本地与服务端能力按显式来源选择，不按登录状态整体替换数据模式。

### 4.2 知识库即工作空间

目录仅列出当前账号有成员资格的服务端库；创建库直接创建 owner 成员关系。库成员、分组、文件夹及页面 ACL 共同约束操作。没有项目资格和项目开放范围两道额外门槛，也不创建默认项目来包住知识库。

Fob 当前是未发布的新产品。移除旧开发模型时直接维护唯一正确 schema，不保留项目兼容层或双轨表。已对 Fob 自有空开发库删除三张废弃项目表；账户、库、文档、附件和评论表保持原有内容。该操作没有访问 Fouc 数据库。

### 4.3 现有数据的独立复制

本次初始化独立新库，未收到 Fouc 用户数据交接输入，不自动搬运账号、会话、令牌、密钥或用户文件。需要交接时按以下顺序执行：

1. 确定需要的知识库、目标账号和授权映射，生成只读来源清单与目标备份。
2. 先导入 Fob 账号映射，再导入知识库及其成员、分组、文件夹、页面、ACL、正文状态、更新、历史、评论和关联资源。Fouc 项目和开放项目集合不进入 Fob。
3. 根据清单复制附件原字节、哈希及元数据到 Fob bucket；重写必要目标 URL，不共享源 bucket 或签名凭据。
4. 校验行数、外键、正文/附件哈希、成员与 ACL，重建派生索引，执行目标端权限和真实打开验收。
5. 浏览器本地内容须从来源 origin 显式导出再导入 Fob，不能假设复制代码会获得另一 origin 的 IndexedDB。
6. 成功后保留交接记录，源端仍保持只读；不自动删除源资源或做双向同步。Fob 登录态、PAT/OAuth 和会话一律重新授权。

## 5. 账号与权限

复制原 Better Auth、验证、找回、资料、OAuth 支持及节流。Fob 使用自己的账户数据库、secret、Cookie 名、回调 URL、trusted origins、邮件链接和 OAuth 应用配置。localhost 的不同端口也可能共享 Cookie 域，因此产品前缀仍必须独立。

同邮箱不表示两个产品的账户、权限或会话相同。库角色与页面 ACL 由 Fob 服务端管理；UI 可见、搜索命中和未来连接器都不能放宽授权。事务、RLS、组合外键、令牌范围、WebSocket 操作重验和撤权断开继续有效。将来可接相同外部 IdP，但 SSO 不替代资源授权。

## 6. 独立开发与部署

技术栈保持 Next.js App Router、React、TypeScript、Tailwind v4、原 Radix-style 控件、Bun/TypeScript 服务和 PostgreSQL。前端沿用静态导出；生产 Nginx 提供静态页面并反代 API/WebSocket。Python 媒体服务独立运行。不引入新的客户端壳或 Next.js API 中间层。

所有安装、开发和生产部署文件在 Fob 内。开发 Web 3001、API/协作/MCP 8721；PostgreSQL 55433、Redis 56380、S3 59010/59011、媒体 8920。独立环境文件由 dev:init 生成；dev:all 保持源码热更新服务常驻，并拒绝冒用兄弟仓库进程。

Dockerfile.web、Dockerfile.server、媒体镜像、compose.production.yaml 及数据库/队列/存储初始化完整保留。生产配置使用独立 HTTPS Web/S3 origin、非超级用户运行角色、认证与存储密钥。完整镜像启动、TLS、公网存储、SMTP/OAuth、模型与真实媒体解析仍需目标环境验收，不能由静态配置检查替代。

## 7. Fouc 的未来连接

本次不修改 Fouc。后续在 Fouc 独立实现 Fob 连接器，通过实例 URL 和显式授权调用公开 HTTP API/MCP，先接搜索、读取、引用和原文跳转，再接授权写入。

Fob 是自身知识的唯一权威。Fouc 只保存外部引用与证据，不直接读取 Fob 数据库，不凭 Fouc 项目成员资格跳过 Fob ACL。跨产品引用包含实例、库和页面身份。

## 8. 实施顺序与完成门槛

1. 记录来源提交/脏文件与复制基线，在同级目录建立独立 Fob 仓库。
2. 复制知识、公共控件、身份、主题、设置、布局、桌宠和处理服务；复制切换器设计后改为知识库语义。
3. 统一唯一知识系统导航；让知识库成为唯一工作空间，删除前后端项目实体、关联、菜单与契约。
4. 隔离账户、Cookie、环境变量、端口、数据库、bucket 和队列，建立独立开发与生产入口。
5. 联调创建/切库/重命名/删除、成员 ACL、标题正文搜索、通知、页签与链接；验证编辑和刷新不丢内容、切库不串数据。
6. 执行必要类型/边界/领域测试及一次真实桌面和窄屏流程，审查复制基线适配，复核前端规则。
7. 有明确输入时按 §4.3 进行只读数据交接；无输入时如实交付独立新库。
8. 清理临时文件，保留开发服务，核对 Fouc 未变并提交 Fob。实现进度记录于 .spec/tasks，不再建立第二份设计说明。
