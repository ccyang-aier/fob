# 代码组织与性能

Fob 是 Web 客户端、TypeScript 业务服务与 Python 媒体服务组成的产品。产品、权限与部署边界仍以 [产品架构](fob-product-boundaries.md) 为准；本文维护源码组织和性能约束，执行证据见 [改造记录](../../.spec/tasks/code-organization-performance.md)。

## 组织原则

- 按能力拥有实现：组件的视图、样式、文案、测试和专属辅助代码放在同一个目录；导入导出、数据协议等无界面逻辑归对应能力，不放进 `components`。
- `src/components` 仅容纳跨功能控件；`src/components/ui` 保留基础控件。业务组件留在其功能内，不通过根组件目录反向依赖业务实现。
- 单文件控件保持单文件；需要多份配套文件时才建立目录。目录入口直接提供组件，不增加只转发内部实现的兼容文件或全量聚合出口。
- 富内容按 Mermaid、白板、PDF、链接卡片分开维护；画布外框和放大预览作为两类图形共用的组件。编辑器文档工具、导出与选区工具分开维护；文件预览按格式组织。
- 跨领域调用使用公开入口；边界检查同时覆盖静态导入、重导出和动态导入。源码搬迁保留迁移基线的来源身份和目标路径，继续校验内容，避免为通过检查保留旧路径空壳。

## `shared` 的职责

保留 `@fob/shared`，因为当前生产源码中 Web 有 121 个文件、业务服务有 118 个文件消费其中的公共模块。正文 schema、块 ID、Markdown、协作原点、评论、模板、检索和权限契约必须在读取、写入、导入导出与服务端校验时保持一致。将这些代码放回前端会使服务端反向依赖 UI，复制两份则会产生正文兼容和权限语义漂移。

共享包只拥有跨运行时的纯契约和领域语义，不依赖 React、浏览器环境或服务端实现。按领域子路径导入；仅供业务服务使用的模型目录 schema 归模型模块，开发种子归服务端脚本，避免把 `shared` 作为杂项目录。公开包接口的调整同步更新全部调用方与构建配置。

## 性能约束

- 先确定触发条件和重复工作，再优化；不以批量增加 memo、延迟显示或减少内容换取表面流畅。
- 编辑器选择变化不应触发与内容无关的全文扫描。文档搜索的查询与高亮根据正文、查询词、大小写和当前结果分别失效；任务统计跟随正文版本，兼容远端更新与撤销。
- 缓存以不可变正文或完整渲染输入为键，设定生命周期或容量边界；错误允许重试。避免每次 React 渲染都重复序列化大正文。
- 保留现有按需加载的 Excalidraw、Mermaid、PDF、Office 与语法高亮，以及不可见 WebGL 背景暂停机制。当前 Tiptap 已默认关闭事务驱动的整页 React 重渲染，不能把重复设置相同选项当作性能改进。
- 用大文档回归、确定性的工作量比较和真实页面交互证明收益；开发环境耗时只作诊断，不作为生产帧率结论。

## DOM 自动化

菜单测试使用同一 Happy DOM realm 的构造器与绑定方法，组件卸载后恢复全局环境。事件目标、`instanceof HTMLInputElement` 和捕获阶段键盘处理必须与浏览器一致。每个场景独立初始化，关闭断言等待 Radix 的焦点恢复任务；避免依赖上一项测试的星标状态。DOM 断言优先输出布尔值或关键属性，避免失败时打印整棵循环引用 DOM。
